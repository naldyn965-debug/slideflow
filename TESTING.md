**Regression comparison.** It compares the Design System JSON from the version 3 and version 4 engines, ignoring `version` and `analyzedAt`. A re-check of version 3 against version 4 over the repository fixtures plus the FOOD deck finds the same three pre-existing decks changing. The comparison script and the list of 31 decks behind the reported total are not committed to the repository, so the 28 of 31 total itself cannot be reproduced from the repository alone.

**Mutation checks.** Seven one-off mutations of `sizeFloors()` in `js/pptx/design.js`, one per scaled threshold (body, title, footer, small text, low body size, large text, large bold text): each threshold was replaced by its unscaled reference value, and the analysis suite failed every time (7 of 7 detected). This is not a committed script. To repeat one, change a single `f(n)` to `n` in `sizeFloors()` and run `npm run test:analysis`.

**Execution limitations.**
- jsdom could not be installed in the authoring sandbox, so the analysis suite ran through Chromium's DOMParser instead. `parser.js` and `design.js` are the same files either way, but a native jsdom run has **not** been done and is not claimed. To close it: `npm i`, then `npm run test:analysis`, and again with `FOOD_PPTX=/path/to/Brown_and_Green_Modern_Food_Presentation.pptx`. Record the counts here.
- The 31 FOOD checks need the real deck (about 27 MB, not committed); without it they print SKIPPED and the total is 206.
- The e2e suite needs Chromium (`npx playwright install chromium`).
- The Firebase path (auth, Firestore, Storage, rules in the emulator, CSP against live endpoints) has never been run. That includes writing a re-analysed version 4 design over a stored version 3 design; the e2e check covers Local mode (IndexedDB) only.
