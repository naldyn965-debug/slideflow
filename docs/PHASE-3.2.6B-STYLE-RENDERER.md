# Phase 3.2.6-B: the renderer draws style records

Second stage of style editing. The renderer can now **draw** the style records of 3.2.6-A: text colour, size, font, bold, italic, shape fill and outline colour. Only `js/render/render.js` changed in the code. **No** controller, UI, XML, export or undo/redo change (a test checks that nothing outside `render.js` calls or defines `setStyle`). Nothing yet *produces* records in the app: the controller does not know them (stage C); the renderer API is exercised by tests with records from `createEditState().commitStyle(...)`.

## API (the handle `renderSlide()` returns)
- **`await handle.setStyle(id, record)`**: apply a style record, or take it off with `null`. Resolves to `true` when something was drawn; `false` for an element it cannot style (unknown id; anything but a plain `sp` shape or `cxnSp` line: pictures, tables and groups are never restyled, whatever the record says; a text style for an element that has no text box), when the record is empty, or when a newer call for the same element took over. Never throws.
- **`renderSlide(scene, host, { width, styles })`**: `styles` (an array or a Map of records) is applied after the first drawing, by the same path as `setStyle`.
- **`handle.setText(id, text, refit, edited)`** (the controller's call) now remembers the text it was given and draws it **with the element's style record applied on top**. A style therefore survives a committed text edit, and a text edit survives taking the style off, without the controller knowing about styles.

The renderer decides nothing about what a record means: it imports only the pure functions `effectiveStyle` and `effectiveText` of the edit-state and never holds or changes an edit-state. The Scene Model is not written.

## How it draws
- **Fill and outline colour:** the shape's SVG is built again by **the same builder** as the first drawing (`buildShapeSvg`, split out of `renderShape`, same output for an unstyled shape) from `effectiveStyle(e, record)`: a solid fill replaces a gradient / pattern / missing fill, the outline keeps width, dash, joins and caps, the flip and the shadow / glow filter stay. The geometry is looked up once, at the first drawing (its support notes are written once). The file's own SVG node is **kept** and put back by `null`, so a reset is byte-identical (gradient ids included). The element's own inline position, size and transform are not touched, so a moved or resized element stays where it is.
- **Text:** the text box is drawn again from the text last given to `setText` (or the file's) with `effectiveText({ text }, null, record)`: colour, nominal size, family, bold, italic on every run and on the default run; hyperlink runs keep the theme's hyperlink colour (and underline); RTL direction and language are untouched; the family override is followed by the Arabic fallbacks for RTL runs. The text box keeps its rectangle.
- **Stored `fontScale`:** the style's size is the **nominal** size (what `<a:rPr sz>` would hold). An element with a text style is drawn as an *edited* shape (3.2.5-C): `data-fit-base` = the stored scale, so `fitText()` starts from full size. A size record of 30 on a shape stored at 62.5 % draws 30 px (shrinking only if it does not fit); a record without a size (say, only bold) draws the shape at full size too, as a text edit does. Shrink autofit, the fit note and the support level follow the new text and are cleared again by `null`.
- **Fonts:** the faces the styled text needs (bold, italic, a new family) are loaded **before** the text is drawn and measured (`setStyle` awaits `loadFontsFor`). The synchronous `setText` path draws at once, asks for the faces, and **fits again when they have arrived**.
- **Races:** each element has a call counter; an older call that finishes after a newer one reports `false` and draws nothing.
- **CSP:** nothing new reaches the DOM except CSSOM properties and SVG attributes (no `style` attribute string, no `<style>`, no HTML string); a test scans the code.

## Tests
`tests/selection.mjs`, section "Phase 3.2.6-B" (47 checks) with the fixture of 3.2.6-A, which gained an RTL shape and a flipped, shadowed shape (`make_fixture_p326a.py`): unchanged rendering (null and unknown / unstyleable elements leave the DOM byte-identical), fill and outline on a solid, missing and gradient fill, group child and connector, byte-identical reset (and the very same SVG node), colour / size / family / bold / italic, mixed runs and the hyperlink run, RTL, font loading before drawing (a spy on `document.fonts.load`), stored `fontScale` and shrink autofit with the fit note cleared by `null`, text edit + style in both orders and with the real controller (a typed character on a styled shape), moved / resized elements, races (text and SVG, a slow face), `renderSlide({ styles })`, and static guards.

## Limitations (exact)
- **Nothing in the app produces or applies records yet:** the controller does not call `setStyle`, a slide drawn again by the controller (a new `renderSlide`) shows the file's styles until the caller passes `styles` or calls `setStyle`; `reset()` does not know styles; no UI; no undo / redo. That is stage C.
- Only what 3.2.6-A can record: solid fill colour, an existing solid outline's colour, text colour / size / family / bold / italic on **every** run; no per-run styling.
- **Support notes and reports are not recomputed:** a gradient replaced by a solid colour keeps its "approximated" note; the Fonts list of the Rendered tab and the report read the file's runs, not the styled text.
- The family is drawn only if the browser has it or a self-hosted substitute exists (Carlito, Caladea, Liberation, DejaVu); DejaVu has no italic. A family that is neither falls back to the generic one.
- A text style makes the element an *edited* shape: its stored `fontScale` is not applied (it is fitted from full size, like a text edit), and a stored `lnSpcReduction` stays as drawn; nothing is written back to the file.
- An element with a fill record whose file fill was a picture is refused by 3.2.6-A; the renderer would draw such a record on a shape of kind `sp` only if the SVG has an image (not reachable through the edit-state).
- Fonts that load slowly can show the fallback face for a moment on the `setText` path before the second fit.
